### How the work has been done (keep doing it this way)

- **A branch per package or slice** (`wp/<ids>-<slug>`; D-059), tests first or with the code, `npm run check && npm test` (about 11 minutes on a quick PC now: the realm soak plays three 24-moon games), the UI gate and screenshots for anything visible, docs (CHANGELOG, roadmap ✅, GDD "implemented", DECISIONS), a PR with What / Why / How / How tested / Screenshots / What the owner should verify,
  **merged with a merge commit only when all eight CI jobs are green**. There is no `gh` CLI here: PRs are made and merged with the REST API and the token from `git credential fill`. Stacked PRs (H1 → H4) are merged in order; each branch contains the one before it.
- **Measure first, then fix**, and let the measure stay: N10's headline suite found a writer fault, R7's soak a levies band that missed the truth one time in five, F9's tour 87 text sizes under 12 px and 40 things a keyboard could not reach, a CI soak a headline word the scorer did not know, **and H3's coherence check a lord who commanded hosts from a cell, a captive "holding a feast", and men arriving who had never set out** — faults 800 tests and a 200-turn soak had not seen. A bench that has found nothing has not yet been made hard enough.
- **The CI runner is four times slower than the lead's PC and runs everything at once.** G's first CI run failed on every job for a timing guard (the realm sample took 190–480 ms where it takes 1 ms now) and then on a 15-minute child timeout. **Any pass over many houses must not scan the world per house**: `figuresIndex(state)` (`engine/realm/figures.js`) is the shape to copy; `standing()` and `project()` take it as a last argument. A timing test should have 3–4× headroom on the lead's PC.
- **Read the picture.** Every UI package was looked at in both sizes before it was called done; that found a card covering a castle's name, a tab strip that wrapped, an icon drawn in the wrong colour, a Settings sentence that told the player to "replace the score" of a music system that has no score.

### Tips and traps learned the hard way

- **Windows** (CI and the owner's PC): a dynamic `import(path)` needs `pathToFileURL`. A Windows checkout has CRLF: never regex over source files with `\n` alone (tests read files and `.replace(/\r\n/g, '\n')`). Edit scripts: read, `split(CRLF).join(LF)`, edit, write back the same endings.
- **In this shell**, backslashes in heredocs and in strings passed through `node -e` are traps (a `\s` lost its backslash and split names on the letter "s"; a `\n` became a real newline in a script): write edit scripts and anything with a regex with the file tool. **A heredoc containing an apostrophe can fail to parse**: write the file with the file tool.
  **`String.replace`/`rep` replace every occurrence**: anchor on something unique.
- **A command started with `&` inside a background task is killed when the task ends**: run long things in the foreground with a timeout or as the background task itself. **Never run two full `npm test` at once on one machine** (`tests/http.test.js` has a fixed port; the timing tests want a quiet PC); a second checkout for another branch is `git worktree add ../x <branch>` (the stash stack is shared: never a bare `git stash`).
- **The soak tests**: `tests/realm-soak.test.js` plays three 24-moon games in three processes (about 5 minutes each on a quick PC) and now waits three-quarters of an hour and says how a game ended (killed, signal, exit code, peak memory). **`scripts/soak.js` takes a random seed from the clock**: a failure there is a real bug that only some seeds show; it prints the seed (`--seed N --houses <house>` plays it again).
- **The coherence check** (`npm run coherence -- --play <house> --seed N --turns 24`) is a bug finder, not only a report: run it after any change that touches captives, regents, hosts, riders or facts' actors. Its A class should stay empty on any seed; if it does not, the fact it names has an id (`f20.246`) and `facts.jsonl` has the rest.
- **Leaks by spread:** `server/view.js` `playerView` spreads `...state`, so every new top-level state field reaches the browser unless it is deleted there (D-069). Every new field: strip it, and add a non-interference test. **A fact the player has not been told yet must not be drawn.**
- **Content is data, built by a script when it is many rows**; **a new house or holding changes the world's numbers** (`ECONOMY.lesserDomain`, `regionOutput`, `scripts/balance-sim.js`, the realm ledger's bands, every prompt that lists the world: `UPDATE_SNAPSHOTS=1` and read the diff). **A name that is also an English word is a trap for the scribe and the scorer** (D-099).
- **Facts are not in `state` between turns** (they are in `facts.jsonl`). **Canon gravity owns the story's dates**: a test that needs a season to pass or a lord to die needs `canonGravity: 'sandbox'`. **`emit` (`engine/facts/log.js`) names the regent, not a captive lord, as the doer of a house's acts** (D-102): a new kind of house act belongs in its `BY_HOUSE` set.
- **`UPDATE_SNAPSHOTS=1` rewrites every prompt snapshot**: run it, look at `git diff --stat`, and `git checkout` the ones you did not mean to change. **Portraits are painted on demand** (a screenshot of a list must wait for them). **The root font size shrinks in a small window**: `rem` sizes under 0.93 are wrapped in `max(…, 12px)` and a static test holds it. **Kill by PID, never `pkill -f` a pattern that is in your own command line.**

**The owner's checklist** (GDD 15 §8; each step is one command and what to look for):

1. `git pull` → `npm start` on Windows → the title screen loads; a new game as Stark: the welcome page, **Begin**, three tips.
2. **Settings → Model**: pick the llama-swap endpoint (`http://127.0.0.1:8033/v1`) and the profile named in §3; *Test connection* passes with *JSON schema supported: yes*.

4. `npm run playtest -- --house stark --turns 12` and `--house blackwood --turns 12` → paste the reports; **each ends with the coherence section**: Class A should be empty, Class B at most one in ten turns.
5. **A 20-minute play as Stark:** the muster, the King's arrival, a letter to Riverrun, an audience with Roose. Does the map agree with the chronicle? Does a promise made in a letter show only when the answer lands?
6. **Listen** (nothing of this was heard by the lead): Settings → Sound & voices. `npm run fetch-music` (or your own files in `public/music/war/`, `winter/`, `north/`…) and play: does the music change with war, with winter, with the North? ## 3. Model guidance

- **The model built for this game is Maester-12B** (a 12B-class base, 4-bit, + one LoRA adapter; llama.cpp b11242 behind llama-swap; two ids of one process: `maester-12b` with the adapter for interpret, mind, director, audience, council and consolidate; `maester-12b:plain` without it for the narrator and the untested call kinds). Read `local-ai/REPORT.md` and `local-ai/MAESTER-12B.md`. Measured: ~75 tok/s, 9.7 GB VRAM on the owner's 12 GB card; interpret 88 % on the unseen orders (untuned 85–86 %), mind 89 % in character with 2 fallbacks instead of 16; narrate did not improve (hence `:plain`). **Profiles are 64k context: never recommend a larger one.**
- **The server flags** (from `local-ai/deploy/llama-swap-maester.yaml`, the owner's own entry): `-c 65536 -ngl 99 -fa on -ctk q8_0 -ctv q8_0 -ub 1024 -b 2048 --parallel 2 --kv-unified -cram 4096 --jinja --cont-batching --metrics`, sampler `--temp 1.0 --top-p 0.95 --top-k 64 --min-p 0.0` (no other sampler flags: `--min-p` made narrate worse), the adapter loaded with `--lora` beside the base and **never merged into a 4-bit file**. Two slots over one 64k pool; **never pin slots** (`slot: null` in every route: two requests pinned to one slot livelock llama.cpp).
- **The routing block for `config.json`** is `local-ai/deploy/game-routing.json` (merge it in): `default` → the tuned id, `narrate`, `letter`, `advisor`, `counsel`, `polish`, `probe` → the `:plain` id; `allowModelSwaps: true` (one process, so no swap), `contextTokens: 65536`, thinking off for every call (the schemas do the work).
- **Temperatures and budgets** are per call kind (`server/ai/models.js` `CALL_DEFAULTS`; a route may override them): probe/interpret 0.2, mind 0.6, director/audience/letter/council/counsel 0.8, narrate 0.85, advisor 0.7, polish 0.4, **weaver 0.3**, consolidate 0.3, scribe 0.1; deadlines 8 s (scribe) to 300 s (narrate, consolidate), settable under `deadlines`. `npm run model:check` says what a route will do.
- **To switch the narrator to another model:** set `models.narrate` (and `letter`, `advisor`, `counsel`) to the id; keep it in the **same llama-swap group** as the rest, or the swap (about 20–25 s) is paid per call and the router refuses unless *Allow model swaps* is ticked.
- **The narrator** writes scenes on top of the deterministic writer's cards: with no model, on the mock, and on a failed call, the writer's card stands (100 % through the scorer; `npm run bench -- --suite headlines`). `narratorMode` `scenes` (default) or `cards` (the model also says the card; needs it to keep the scorer's rules — §4).
- **The Weaver** (`weaver: true` in config, or Settings → Model): off by default; at most one custom a game month, never the player's house; the rule is checked in the sandbox before it is kept. **Not tried on a live model.**
- **The scribe** (`models.scribe`, a ~350 MB model on the CPU, its own server) is optional; with none, rules alone mend the line. Speech-to-text and text-to-speech run in the page on the CPU (WASM), never on the GPU; `npm run fetch-ears` and `npm run fetch-voices` put the files where they are read.
- **Pace on the lead's PC with the mock** (the engine alone; `npm run bench -- --suite latency --mock`): a 7-day jump takes 0.6 s and a 30-day jump 1.8 s in the first turns, rising to about 5.5 s for 30 days from the eighth moon on and staying there (the lords' minds 1.3 s, the engine 3.6 s; a 7-day jump is roughly a third of that); an audience 0.1 s, an order's receipt 0.1 s. The model's own time is added to this, and `--suite latency` on the live model says how much. The realm soak's five minutes a game is its audit, not the turn. **On Maester-12B (the same PC, `maester-12b` with the adapter and MTP, 9.7 GB):** a 7-day jump 19.4 s median and 21.3 s at the 95th (the lords' minds 13 s, the narrator 4 s, the engine 0.4 s), a 30-day jump 39 s (the minds 28 s), an audience reply 5 s, an order's receipt 0.1 s; the calls: a mind 4.1 s, a scene 4.2 s, a council 8 s, a consolidation 6 s. The minds dominate: six lords a week, two at a time. `"minds": 3` halves it if the pace is wanted over the realm's life.

## 4. Fine-tuning guidance

**My recommendation, after playing the finished game on Maester-12B (§0): do not fine-tune yet.** Every suite met its gate on the model as it is (interpret 95 %, mind 86 %, narrate 95 % true first time, the pace of the design) except the audience's 100 % — and that miss is two or three lines in eighty, a persona who objects in words after the engine settled *agree* or *obey*. The game's own checks catch it (a promise is bound to the verdict, and the UI shows a contradiction), so it costs the player a clumsy line, not a wrong world. A tuning round costs a Kaggle week and *risks* the other gates; spend it only when the owner's own play finds something the suites do not. If and when you do, the order below stands, and the evidence for it is rows 12–16 of `local-ai/MODEL-WISHLIST.md`. **Not before the owner has run §2 on their own PC too.** An adapter learns the prompts of **one commit**; the prompts are now frozen for this handoff (snapshots in `tests/__snapshots__/prompts/`), so this is the moment, *if* the bench says so: **interpret exact-action below 95 %, mind in-character below 85 %**, or one kind of call that keeps failing the game's own checks (the audience suite, the narrate suite's faults by rule).

**The recipe is `scripts/finetune/README.md`** (H4), step by step: turn on `"logCalls": true` and play (or run the playtest) on the model you mean to tune; `build-dataset.mjs` turns `saves/<game>/llm-calls.jsonl` into examples the game's own checks accepted (no foreign script, no game word, nothing from after 298, under 3,400 tokens) and into **preference pairs** (the answer the game refused beside the one it accepted when it asked again); `train.py` is QLoRA with an optional preference stage; `export-gguf.mjs` and `llama-swap-profile.mjs` make the adapter a GGUF beside the base and the 64k entry that serves it (adapter on and `:plain`). Then the bench before and after, on the same commit. The first adapter's synthetic-scenario pipeline and its results are `finetune/westeros/` and `local-ai/TRAINING.md`; two free Kaggle T4s trained the 12B in about sixteen GPU-hours. **`train.py` was written without a GPU:** its dry run is tested, the first real run is its test.

**What to tune first, in order of value:**

1. **The narrator's cards (the `cards` mode), if the model is to write them:** the 12B fails the headline scorer's rules too often, and the writer's own card is better in most cases. Train on **pass/fail preferences with the scorer as the filter** (`pairs.jsonl` from a play in `cards` mode; `server/ai/validate/headline.js`); never on book text. Until then leave `narratorMode: scenes`.
2. **Audience replies that agree in words while the verdict is "refuse"**, or promise what the engine will not let (the UI now shows that as a contradiction to the player): `--suite audience` measures it; the pairs from refused-then-accepted audience calls are exactly the data.
3. **Scene openings are formulaic** ("The wind…"): try one line in the prompt first, then varied openings in the accepted `narrate` examples.
4. **The interpreter's dossier does not yet list the seat's own lords by name** (R10 of `local-ai/RECOMMENDATIONS.md`): change the prompt, regenerate the snapshots, *then* collect. The R8 validator ("six rangers") is game-side and worth two orders for every model.
5. **`mindRealmBrief`** (config; off because the first adapter was taught the dossier without it): turn it on, play and collect, so the next adapter learns the dossier with it.

Never train on book text, on anything from after 298, or to clone a voice.

- **What the live model does badly** (rows 12–16 of `local-ai/MODEL-WISHLIST.md`, the next fine-tune's list): scenes open on a smell and close on a trivial watched detail ("a speck of dust") in most of a playtest's scenes; 11–14 % of the lords' mind replies name an option that is not on the list (the retry or the house ways rescue them); the narrator names a place the story does not hold (a Bolton scene at "the Dreadfort" in a week that never mentions it) (6 of the playtests' 19 scenes failed the game's checks on the first telling, and the retry mended them; the suite's sixty weeks were 95 % true first time); the prisoner situations of the mind suite are 4 of 13 in character; an insulted own man ordered to obey, or a lord settled as *agree*, sometimes refuses in words (2–3 lines of 80).

It is Class C (reported, not gated). The places to look: `shared/marches.js` (`tollAlong`, `route.paid`, which a re-plan resets) and the `behaviour` facts' importance. **It does not check where a person is by day** (the facts carry no per-day whereabouts; it checks one person reaching two places in a day), and it checks "the player's own men" only against the last turn's realm books when no orders are pending.
